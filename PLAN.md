# Gold Compass for WoW Forever: build plan

Status: plan only, no code written. Research date: 2026-11-18.
Working name: **GoldCompass** (folder `GoldCompass`, command `/gc`). Name chosen by the owner (2026-11-18); "Magpie" was rejected because a group-loot addon already uses it and `/magpie`.

Every claim below is either **verified** (read today in a source file or an official page) or marked **unverified**. Nothing was tested in the game: no WoW Forever client is installed on this Mac.

---

## 1. Goal, and what is deliberately not built

**Goal.** A player leveling from level 1 asks "how do I make gold now?" and gets a direct answer. Three features, in this order: (1) a **profitability map** that ranks zones by estimated gold per hour of gathering, using where GatherMate has seen herbs and ore and what Auctionator says they sell for; (2) a **smart item tooltip** that names the recipe an item is used in, how to unlock it, what the result sells for, and one recommended action; (3) an **advisor** that says what is worth doing in the current zone and with the current bags.

**Not built, because existing addons already do it:**

| Not built | Covered by |
|---|---|
| Scanning the auction house, storing prices | Auctionator (also TSM, Auctioneer) |
| Recording node positions, drawing them on the map | GatherMate2 + GatherMate2_Data |
| Ranking crafts by profit, "how many can I craft now" | Forever Ledger, Profiteer Forever, CraftProfit Forever, ForeverProfit |
| Tracking gold earned per session | GoldWatch |
| Buying, posting, cancelling auctions | Auctionator, Forever Ledger |

**The addon only advises.** It reads data and shows text. It never buys, sells, posts, mails, crafts, moves, targets, casts or clicks for the player, and never calls a protected game function. The only things it opens are its own window and, when the player clicks a zone row, the world map. This keeps it inside Blizzard's addon policy.

## 2. Decisions and open questions

### Decisions taken

| # | Decision | Why |
|---|---|---|
| D1 | Herbs and ore only for the map. No fishing, skinning, cloth or chests. | The Forever data shipped by GatherMate2_Data contains only herbs and mining (verified). |
| D2 | Node positions are read through GatherMate2 at run time, never copied into this addon. | GatherMate2_Data has no stated licence (verified: none on the repo), so its data cannot be redistributed. |
| D3 | Prices come from Auctionator's public API only. TSM and Auctioneer are not supported at first. | One source is enough to ship; Auctionator is listed for Forever (verified). |
| D4 | GatherMate2 and Auctionator are *optional* dependencies with an explicit "not installed" message, not hard dependencies. | With a hard dependency a missing addon makes ours silently not load: a blank screen with no explanation. |
| D5 | Gold per hour uses a fixed standard pace first (60 nodes per hour). Measuring the player's real pace is deferred until play shows the estimate misleads. | YAGNI. |
| D6 | The tooltip adds at most 3 lines and is silent in combat. | Readability; and Forever applies the Midnight client's combat restrictions on addons (verified from a secondary source). |
| D7 | Recipe and quest data is a build-time copy of Forever Ledger's MIT data files, with attribution, regenerated by a script. | Forever Ledger keeps its data private to itself (verified: no public table or API), so it cannot be read at run time. See question Q1. |
| D8 | Libraries: Ace3 (AceAddon, AceConsole, AceEvent, AceDB, AceGUI) and LibStub, pulled at packaging time. No minimap button. | Ace3 is the standard maintained library set; GatherMate2 embeds the same on Forever (verified). |
| D9 | English only at first. | YAGNI. Node and item names still appear in the player's language because they come from the game and GatherMate2. |
| D10 | Licence MIT. | Compatible with reusing Forever Ledger's MIT data. |

### Open questions (3), each with a recommended answer

**Q1. Should the tooltip stand alone, or complement Forever Ledger?**
Forever Ledger already prints sell / vendor / disenchant / "keep for quest" in the tooltip. Two addons each printing a verdict is noise.
*Recommended:* complement. When Forever Ledger is loaded, GoldCompass adds only what is missing (the named recipe, how to unlock it, the profit). When it is not loaded, GoldCompass prints its own single action line. In parallel, ask the Forever Ledger author for a small public API so the data copy (D7) can be dropped later.

**Q2. Where is the Forever client, and who runs the in-game checks?**
Forever appears to still be in beta (Forever Ledger's page says "tested in the Forever beta"; unverified whether access is open). No client was found on this Mac.
*Recommended:* the owner confirms access and the machine. Every step below ends with a 5-minute in-game checklist, plus a `/gc dump` command that saves the last result to disk so the builder can read real output instead of trusting a report.

**Q3. Is "map" a ranked list, or an overlay painted on the world map?**
*Recommended:* a ranked list first. Clicking a zone opens the world map on that zone, where GatherMate2 already draws the nodes. A coloured overlay on the world map is not built unless the list proves insufficient.

## 4. Build steps

Sizes are rough. "Lines saved" compares with writing the same thing by hand.

### Step 1. Zone ranking in chat (feature 1, usable end to end)

- **Goal:** the player types one command and reads which zones pay best for gathering right now.
- **Owner sees in game:** `/gc map` prints up to 10 lines such as `1. Westfall  ~14g/h (estimate)  Copper Ore, Peacebloom  [prices 1 day old]`. Only nodes the character can gather today count. A character with no gathering profession sees the same list titled "if you learn Herbalism / Mining".
- **States, from the start:**
  - Loading: "Reading node and price data..." while item names load, with a 5-second limit, after which unknown names show as "item #1234".
  - Empty: "GatherMate2 has no nodes yet. Install GatherMate2_Data, then /gathermate, Import." / "No price scan yet. Open the auction house and run an Auctionator scan."
  - Error: "GatherMate2 is not installed" / "Auctionator is not installed", each with the fix; any unexpected failure prints one line and never a Lua error popup.
- **Reused:** GatherMate2 + GatherMate2_Data (16,433 node positions, collection, storage: several thousand lines and all the data); Auctionator (auction scanning and price history: several thousand lines); Ace3 for the command and saved settings (about 100 lines).
- **Hand-written, nothing suitable exists:** a table of about 45 rows (node, item it gives, skill needed, average yield), generated from Forever Ledger's MIT item list where possible and checked by hand; and the ranking calculation (about 80 lines).
- **Size:** about 200 lines plus the table. One day.
- **Verified in game:** on a low-level character, run `/gc map` in four situations (no GatherMate data; data but no scan; fresh scan; one profession learned) and check each message. Hand-check one zone: count its nodes and multiply by the Auctionator tooltip price; the result must match the printed figure within rounding. `/gc dump` saves the ranking to disk for the builder to read.
- **Can be cut:** the "if you learn..." variant; the zone level filter (show all zones, tag the dangerous ones).

### Step 2. Profitability window (feature 1, comfortable)

- **Goal:** the ranking becomes a proper window the player keeps open while planning.
- **Owner sees in game:** `/gc` opens a window listing zones with gold per hour, the two best items, price freshness, and a tag for zones above the character's level. Clicking a zone opens the world map on it, where GatherMate2 shows the nodes. A "Refresh" button and an automatic refresh after an auction scan.
- **States:** a visible "Loading..." row; the three empty messages from step 1 shown inside the window with the fix; "Refresh" disabled while a refresh runs; a "prices older than 7 days" banner.
- **Reused:** AceGUI for the window, scrolling list and buttons (about 250 lines saved); GatherMate2's map pins instead of drawing our own (about 500 lines saved); step 1's calculation unchanged.
- **Size:** about 150 lines. One day.
- **Verified in game:** open the window in each state; click three zones and confirm the map opens on the right zone with pins; scan the auction house and confirm the figures change without reloading.
- **Can be cut:** automatic refresh; sorting by column; the level tag.

### Step 3. First public alpha

- **Goal:** other players can install it from CurseForge.
- **Owner sees:** a CurseForge page with an alpha file listed under WoW Forever; installing it through the CurseForge app works on a clean setup.
- **Reused:** BigWigsMods packager GitHub Action (the one GatherMate2 uses), which builds the zip, pulls Ace3 and uploads (about 100 lines of release script saved).
- **Size:** configuration only. Half a day.
- **Verified in game:** install the published file on a client with no development copy and run the step 1 checklist once.
- **Can be cut:** nothing. Can be postponed until after step 4 if the owner prefers to publish with two features.

### Step 4. Smart item tooltip (feature 2)

- **Goal:** hovering an item in the bags says what to do with it and why.
- **Owner sees in game:** up to 3 extra lines on bag items, for example:
  `Used in: Minor Healing Potion (Alchemy 1, trainer)`
  `Result sells ~3s 20c, profit ~1s 10c each (estimate)`
  `Do: craft Minor Healing Potion` (or: sell on auction house / vendor / disenchant / keep for quest "Name")
  One action only. With Forever Ledger loaded, the action line is left to it (see Q1).
- **States:** "price unknown, scan the auction house" instead of a profit; "recipe source not confirmed on Forever" when the source comes from original Classic data; nothing at all in combat; items with nothing to say get no lines.
- **Reused:** Forever Ledger's MIT data, copied at build time by a script: Forever crafts with ingredients and skill (generated from the Forever game files), recipe sources (trainer, vendor, drop, quest) and quest items. This avoids writing or maintaining any recipe database (about 700 KB of data). Auctionator for sale, vendor and disenchant prices. The game's own tooltip hook.
- **Hand-written, nothing suitable exists:** the rule that picks the one action (about 60 lines) and the line formatting.
- **Size:** about 200 lines plus generated data. Two days.
- **Verified in game:** hover ten chosen items covering each action (a herb used in a profitable craft, a grey item, a green armour piece, a quest item, an item with no price) and compare each with a hand calculation; hover during combat and confirm no lines and no error; repeat with Forever Ledger enabled and confirm no duplicate verdict.
- **Can be cut:** disenchant as an action; "how the recipe is unlocked" for recipes that are not from a trainer; recipes with more than one craft step.

### Step 5. Bags advisor (feature 3, part "with what I carry")

- **Goal:** one screen answers "what can I do with what is in my bags".
- **Owner sees in game:** a "Bags" tab (and `/gc bags`) grouping the bag contents by action: sell on the auction house (with total), vendor (with total), craft (which recipe, how many), keep. A total "your bags are worth about X (estimate)".
- **States:** "Loading..." while items resolve; "Your bags are empty of sellable items"; "No price scan yet..."; refresh when the bags change.
- **Reused:** step 4's decision rule, unchanged (this step is mostly a list on top of it); AceGUI tab.
- **Size:** about 120 lines. One day.
- **Verified in game:** compare the screen with the tooltips of the same items; loot an item and confirm the list updates; empty the bags and confirm the empty message.
- **Can be cut:** the bank; the totals.

### Step 6. Here-and-now advisor (feature 3, part "where I stand")

- **Goal:** one screen answers "what is worth doing right here, at my level, with my professions".
- **Owner sees in game:** a "Here" tab (and `/gc here`): this zone's estimated gold per hour and its best nodes for the character; one comparison line ("Westfall pays about 2x more at your level"); and, with no gathering profession, which one would pay best in this zone. It updates on zone change.
- **States:** "No data for this zone" (cities, dungeons); "Loading..."; the missing-addon and no-scan messages.
- **Reused:** step 1's ranking and step 4's rule, unchanged.
- **Size:** about 100 lines. One day.
- **Verified in game:** walk between two zones and a city and confirm the tab follows; check the comparison line against the step 2 window.
- **Can be cut:** the "which profession to learn" hint.

### Later, only if play shows the need

- Measure the player's real nodes per hour per zone and use it instead of the standard pace.
- TSM / Auctioneer price sources.
- A coloured overlay on the world map.
- Translations.

## 5. Data model in plain terms

**Where each fact comes from**

| Fact | Source |
|---|---|
| Where nodes are, per zone | GatherMate2's database: imported pre-filled data plus nodes the player gathered |
| Which item a node gives, skill needed, average yield | Small table shipped with this addon |
| Sale price, and how old it is | Auctionator, from the player's own scans on their own realm |
| Vendor price | The game (through Auctionator's vendor call) |
| Recipes, ingredients, how recipes are obtained, quest items | Copied from Forever Ledger's MIT data at build time |
| Character level, professions, zone, bag contents | The game |

**How gold per hour is estimated**

For each zone, counting only nodes the character can gather:

```
value of one node  = average yield x auction price x 0.95
zone value per node = average of node values, weighted by how many spots of each node the zone has
pace               = 60 nodes per hour, reduced in zones with fewer than 100 known spots
gold per hour      = pace x zone value per node
```

**Assumptions, stated openly**

- **Pace:** 60 nodes per hour, the same for everyone. It ignores mount, level, competition, respawn timers and fights. Checked once in spike S6. (unverified)
- **Route efficiency:** not modelled. Sparse zones are penalised in proportion to their number of known spots; the threshold of 100 is a starting guess. (unverified)
- **Yield:** 2 items per node on average; rare extras (gems, stones, bonus herbs) are ignored. (unverified on Forever)
- **Auction house cut:** 5% taken off every sale. The listing deposit is ignored.
- **Known spots are not live spawns.** The pre-filled data lists every place a node can appear, so counts overstate what is up at one time. They are used to compare zones, not to predict a count.
- **Selling in bulk lowers the price.** The estimate assumes everything sells at the last scanned price.

**Stale or missing prices**

| Price age | Treatment |
|---|---|
| 0 to 2 days | Used as is |
| 3 to 7 days | Used, zone tagged "old prices" |
| Over 7 days, or never seen | Not used; the item counts at vendor price and the zone is tagged "partial" |
| No scan at all | No ranking; the "open the auction house" message |

**How the estimate is labelled**

- Every figure carries a "~" and the word "estimate"; the window has a permanent footer: "Estimates from your last scan and average gathering pace. Not a guarantee."
- Each zone row shows the age of its prices and a "partial" tag when some items had no price.
- Figures are rounded (to the gold above 10g, to the silver below) so they do not look more precise than they are.

## 6. Distribution

**Repository layout** (the repository root is the addon folder, as GatherMate2 does)

```
GoldCompass.toc          interface 16001, Forever only, optional deps: GatherMate2, Auctionator
Core.lua                 startup, commands, saved settings
Prices.lua               the only file that talks to Auctionator
Nodes.lua                the only file that talks to GatherMate2
ZoneRank.lua             the gold-per-hour calculation
Window.lua               window and tabs (steps 2, 5, 6)
Tooltip.lua              step 4
Advice.lua               the single "what to do with this item" rule (steps 4, 5)
Data/GatherNodes.lua     node table (hand-checked)
Data/Recipes.lua         generated, do not edit
Data/QuestItems.lua      generated, do not edit
tools/build-data         regenerates Data/ from Forever Ledger's MIT files, records the source version
.pkgmeta                 pulls Ace3 and LibStub at packaging time (not committed)
.github/workflows/release.yml
CHANGELOG.md  LICENSE (MIT)  NOTICE (Forever Ledger attribution)  README.md  PLAN.md
```

**Versioning.** Semantic versions as git tags: `v0.1.0-alpha` for step 1, `v0.2.0` for the window, `v0.3.0` tooltip, `v0.4.0` bags, `v0.5.0` here. A tag triggers a release; an `-alpha` or `-beta` suffix sets the CurseForge release type. The TOC version is filled in from the tag. Each Forever client patch that changes the interface number needs a new tag with the updated number.

**CurseForge packaging for Forever.**

1. Create the CurseForge project; put its ID in the TOC.
2. TOC declares `## Interface: 16001` and restricts loading to the Forever game type. The exact combination of load directives is confirmed in spike S1 (the wiki warns that an unrecognised game type is treated as allowed, so an exclude for Retail is needed).
3. Release through the BigWigsMods packager GitHub Action with a CurseForge API key stored as a repository secret. GatherMate2 uses this action and its files appear under WoW Forever (verified); that the packager tags a Forever-only addon correctly is **unverified**.
4. Fallback if the tag is wrong: upload the zip by hand on the CurseForge site choosing game version 1.60.1, or reuse Forever Ledger's MIT upload script, which resolves the game version from the interface number.
5. The CurseForge description states: needs GatherMate2, GatherMate2_Data (with the one-time Import) and Auctionator; estimates only; never automates anything.
